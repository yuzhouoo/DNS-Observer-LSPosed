# DNS Observer v0.6.3-beta5 — IPv6 启动失败与自动修复循环修正

实机 v0.6.2-beta4 日志出现 `PRECHECK_FAILED: reserved route/pref occupied` 和 `EADDRINUSE`，失败后自动修复每 15 秒尝试重启。

本版本：
- 首次 IPv6 启动没有完成真实 UDP/TCP 自检与规则激活，则本次会话不再执行 IPv6 覆盖检测/自动修复；保留 IPv4 正常检测。
- 仅曾经实际成功激活 IPv6 的会话才可以自动修复；每次异常最多尝试一次，修复失败锁定等待手动关闭/检查，避免重复占用端口和修改路由。
- 强制关闭时新增仅针对 DNS Observer Root 代理类名或唯一进程名的旧进程清理（不按端口盲杀），以释放上版孤儿监听；Root 脚本缓存名升级为 v063，确保不会执行旧版脚本。\n- Root IPv6 代理 READY 增加 `pid=`；启动/停止流程使用带会话 token 校验的 Root stop-process 子命令，先 TERM 后必要时 KILL；不会按进程名盲杀其它 Root 进程。
- 监听 bind 失败新增具体协议、地址、端口和 errno 日志。
- route/pref 冲突新增实际占用规则和路由表输出，绝不覆盖不属于本模块的规则。
- 仅勾 IPv4 时完全不启动 IPv6 代理；手动统一关闭仍同时清理 IPv4/IPv6 和旧实验规则。

注意：本版本并不强制清理所有历史孤儿进程。旧版残留的 Root 进程若没有可验证 PID/会话信息，不会被盲目终止，仍须先检查。首次 IPv6 启用失败不等于系统覆盖。新的 PID 与自动修复分支尚需实机验证。

# DNS Observer v0.6.2-beta4 — 统一 IPv4 / IPv6 DNS 接管控制

- IPv4 NAT 与 IPv6 TPROXY **独立复选框**。至少选一项启动。依然只处理 UDP/TCP 53；不覆盖 DoH/DoT/DoQ；IPv6 Root UID 0 不劫持。
- 统一“关闭接管”不参考勾选，发送停止 IPv4 和 IPv6 服务请求，清理 DOBSR53 / DO6G061 / DO6TST55 自有链及相应标记、策略路由、局部规则；不 flush 系统表、不删外部规则。返回残留核查结果。
- **取消自动定时关闭**：正式 IPv6 不再 145 秒退出，也不再 180 秒看门狗定时回滚。异常时 Root 代理关闭仍执行安全清理，避免断网；这不是周期性超时恢复。原 UID 隔离诊断仍为限时测试，但不在主页面上。
- 新增检测系统覆盖：前台服务每约 15 秒读取 IPv4 NAT 和 IPv6 TPROXY 自有规则状态，记录一次状态异常事件到独立事件日志。若开启“被系统覆盖后自动重新接管”，则仅在用户要求接管且没有手动关闭时尝试修复或重启 IPv6 Root 代理；默认关闭。
- 新增开机自启开关：在 Android BOOT_COMPLETED 后，如果“开机自动启动”及“上次仍要求接管”均为 true，则尝试恢复选择的 IPv4/IPv6 代理。手动关闭将清除“要求接管”的状态，所以之后的开机不会偷偷重新启用。
- 主/从/备**仅使用指定 Bootstrap DNS 纯 IP**解析域名：删除 Android 系统 `InetAddress.getAllByName` 优先路径。用户直接配置数字 IP 则直接使用，不触发域名查询；Bootstrap 为空且需解析域名时拒绝启动。
- UI 清理重复的历史实验入口，使用深色圆角按钮、IPv4/IPv6 开关与独立垂直滚动日志框：接管状态、覆盖检测、测速明细、IPv6 Root 日志、测速历史。每一类日志都有复制，关键日志可清空。

## 重要边界

beta4 编译通过不等于已在 OnePlus 12 实机验证持续接管及开机自启。务必先关闭系统 Private DNS 与冲突的第三方透明 DNS 规则，在非关键网络环境逐步检查 IPv4-only、IPv6-only 和双协议启动、手动关闭（查看残留核对），然后再开启自动修复与开机自启。Android 后台启动策略和 ROM Root 权限可能限制开机行为。本版不承诺接管 Android 全部 DNS Resolver UID 及加密 DNS。

# DNS Observer v0.6.1-beta3 — IPv6 DNS53 全局试用（必须手动启用）

基于 OnePlus 12 Android 16 / KernelSU 的实验反馈：v0.5.9 DNS53 UDP/TCP 真实上游转发闭环成功，v0.6.0-beta2 连续 16 轮通过并在手动停止后 `VERIFY_CLEAN`。本版进一步实现**普通非 Root UID 的 IPv6 单播 UDP/TCP 53 接管**，不是默认自动开启，也不包含 DoH/DoT/DoQ。

## 激活顺序（降低故障风险）

1. 用户明确点击「开启 IPv6 全局 DNS53」，并确认网络中断风险；未点击时不写任何 IPv6 全局规则。
2. 在任何 mangle/路由修改前，解析并预检已保存的主/从/备上游 IP，确保 UDP/TCP 实际 DNS 都可用。
3. 创建独立 Root 代理（`DnsIpv6GlobalDaemon`，UDP/TCP `::1:15456`，4 workers / 32 queue，145 秒硬期限）。UDP 使用 Android `Os.recvmsg` + `IPV6_RECVPKTINFO` 获取每个包原始 IPv6 目标，响应专用临时透明 Socket 绑定 **原始目标 IPv6:53**；TCP 使用 `Os.getsockname(accepted)` 检查原始目标 IP:53 并在透明连接回传。
4. 安装 `DO6G061` 独立链、mark `0x40000000/0x40000000`、route table `19754`、priority `15010`；一开始 OUTPUT **仅匹配 DNS Observer 自身 UID**。对 `2001:db8:ffff::53` 和 `2001:db8:ffff::54` 两个不同 IPv6 目标分别发送 UDP、TCP DNS 查询，验证真实上游响应和原始目标源地址。任何失败直接终止，不扩大规则，并核查恢复。
5. 四项自检通过后才调用 `promote`，把 OUTPUT 限制扩到**非 UID 0** 本机进程的 IPv6 全球单播（`2000::/3`）与 ULA（`fc00::/7`）53 端口；仍只拦截本机 OUTPUT，不改 LAN 转发，不影响原有 IPv4 `dns-root.sh`。再进行 2 项回归查询；失败立刻撤销。
6. 145 秒 Root 服务期限、独立 180 秒看门狗；Root 服务退出则尝试自动恢复。提供单独停止/恢复按钮、独立日志及清空按钮。所有清理均要求 `VERIFY_CLEAN`，不调用 `-F OUTPUT`、不碰其他服务的路由表。

## 特别注意

- **不能保证覆盖 Android DNS Resolver 及全部应用**：UID 0 故意排除，防止 Root 上游转发递归；如果某 ROM 的 DNSResolver 以 UID 0 查询，这部分不会被接管。用户态 App 的 DoH/DoT/DoQ 不属于 UDP/TCP 53。
- **不能保证网络不中断**：`recvmsg` 的 IPv6 PKTINFO 是否为真实目的地址、TCP `getsockname` 的表现必须通过这台设备的双文档目标自检确定。即使通过也必须先观察实际应用行为；切勿在无 Root 回滚能力时开启。
- 自检期/启用期的 IPv6 DNS53 请求可能被重定向。若代理异常退出或上游全部失败，尽力自动回滚；独立看门狗是最终后备，**并非毫无条件保证一定恢复**。
- UDP per-query reply socket 新建绑定有并发开销，真实多客户端压力尚未实测。适合本次限时试用，不应当作无人值守长期全局代理。
- 旧 beta2 UID 隔离试运行保留在折叠的“高级诊断”，以便比较与恢复；主/从/备配置、IPv4 REDIRECT 与 LSPosed 监控不变。

### 需要实机返回的日志

主要看 `自检 UDP/TCP 2001:db8:ffff::53`、`...::54`、`PROMOTED`、`UDP_RECV_ERROR`、`TCP_QUERY_ERROR`、`VERIFY_CLEAN`。只有 `PROMOTED` 后才开始实际全局非 Root UID 的有限期接管。

### Box 状态自动适配（0.6.4-beta7）

DNS 接管页面新增“自动适配 Box 启动 / 重启 / 停止”（默认开启）。仅在用户请求的接管会话中工作；关闭 DNS 接管后不再监测，也不会因 Box 启动而自动打开 DNS。

约每 3 秒只读检查 `/data/adb/box/bin` 下受支持核心的真实进程、PID 启动时间、Box 防火墙链及策略路由。连续两次一致才确认变化；正常流量计数和本应用自身规则不参与指纹。状态读取失败显示未知，不当作 Box 停止。

Box 启动、重启或规则更新稳定后，仅重新安装本应用的接管规则；IPv6 重新执行完整 UDP/TCP 自检，失败清理回滚并暂停该会话的重复恢复。Box 停止时先校验现有接管，正常则继续使用，受影响时尝试恢复。首次未成功启用的 IPv6 不自动重试。此开关独立于普通“被系统覆盖后自动重新接管”。

适配不修改 Box 配置或规则，也不绕过其他模块的 IPv6 禁用策略。Box 仍应开启 IPv6、关闭其 DNS 劫持及性能模式。设备上的持久性规则冲突仍需检查实际规则，监测功能不能保证兼容任意第三方配置。

### 状态一致性修正（0.6.4-beta9）

状态以实际代理、规则校验和同一生命周期内的采样为准。覆盖安装/进程重建后，仅保留的启动请求不算“已开启”；显示中断或残留原因，先关闭清理再重新开启。启动、停止及修复过程会使旧采样失效，不使用跨越操作的结果。未知内核状态不重置 IPv6 开关的上次显示。

IPv4 自动恢复使用实际服务状态，并通过当前服务的原会话令牌重装，保证该服务仍能正常清理自身规则。Box 初始化/停止过程只读健康检查仍继续，稳定之前不重装；启动前采集 Box 基线，避免漏掉 DNS 启动期间的重启。重复的 Box 状态不再反复写入设置。IPv6 停止同时检查自身 Root 进程退出和规则清理，不能只凭已发停止信号宣称成功。

### 域瞳与后台任务修正（0.6.4-beta10）

中文应用名为“域瞳”，保留原包名、签名流程和 LSPosed 入口。新增观察之眼 / DNS 节点自适应矢量图标、Android 13 单色主题图标和通知栏单色图标。

周期上游检测不再随每次打开控制页重复调度；任务持久化，由系统安排执行（15 分钟是最小周期，不是准时计时器）。取消令牌按单次任务隔离，旧任务不能结束新任务；仅在接管会话关闭且实际代理未运行时进行快速 UDP/TCP 检测。任务被取消后会中断执行并避免写入中断的测速结果。

接管通知可直接打开控制页、停止接管，并更新最近状态。控制页提供通知授权与后台设置入口，不自动修改系统电池策略。系统重建接管服务时复用已通过校验的 IPv6 代理；仅在系统重建且存在清理需求时先核验清理，再按此前开启请求恢复。重复启动不会覆盖运行中的通知；晚到的启动请求不会取消正在进行的手动关闭。强制停止、系统权限限制和厂商电池策略仍可终止应用，代码不承诺永久存活。

### 详细观察与 IPv6 初始路由（0.6.4-beta11）

修复 Root 旧代理核查在大量进程下超时：先用 shell 内建读取 comm/UID，仅对候选 Root Java 进程读取完整命令，仍核验身份与退出。Bootstrap 在 UDP 失败或截断时尝试 TCP；单个上游解析失败不再阻止其他已配置上游的预检。

IPv6 TPROXY 增加专属 14990/14991 精确初始路由，仅匹配 lo、本次允许的非 Root UID、UDP/TCP 53 及 2000::/3 / fc00::/7，解决无原生 IPv6 默认路由时请求到不了 OUTPUT 标记的问题。探测阶段仅应用 UID，验证后才扩展非 Root UID；UID 0、其他端口、链路本地/组播保持原路径。内核不支持精确选择器即回滚，绝不安装宽泛兜底路由；更早的全局 unreachable 阻断不覆盖，报告其归属策略待用户处理。

主页面“详细观察”默认关闭。开启后增加接管实际收到的 UDP/TCP 查询、查询类型、上游协议/目标、返回地址及响应码；代理无法获取原请求 UID 时明确显示未知，不猜应用。系统私人 DNS 验证、853 端口连接及已验证 DNS 地址的 443 连接属于独立证据：端口或配置不能证明 DoT/DoH/DoQ。系统事件按各自 NetID 获取配置，不再把接管配置套到每条事件。

HTTP 观察需要：详细开关 + 包名白名单 + LSPosed 勾选相应应用作用域 + 重启目标应用。系统框架新增 Hook 需重启系统生效。覆盖已知 Android HttpURLConnection 和 OkHttp RealCall API；仅记录相关 HTTP 调用，不修改请求、不读取/消耗流、不解密 TLS。Content-Type 或有效 GET dns= 报文提供 API 级 DoH 线索；dns-query / resolve / doh 等关键词只能提供疑似线索。应用侧写入校验真实调用 UID 与白名单、限批次和频率，不能伪造系统心跳或他人 UID。仅保留无凭据、无任意 query/token/fragment 的 URL 和 DNS 相关元信息。

数据库从 v3 无损升级 v4，增加来源、协议、证据、明细及结果阶段；CSV 同步扩展。HTTP 调用/连接观察不计入 DNS 成功或失败。Root 明细最多 25 条/秒，HTTP 每 UID 120 条/分钟，队列及数据库均有上限；此模式不是无丢失全量抓包。不覆盖任意原生/Go/QUIC 实现，不能保证解密所有加密 DNS。

### 清理脚本与状态提示修复（0.6.4-beta12）

- 修正清理入口的 shell 否定命令拼写；增加空状态及仅剩策略规则时的真实脚本回归测试，避免静默跳过残留清理。
- 将泛化的“会话已中断”改为“服务未运行 · 待清理”，说明这是保存的开启意图与实际服务状态不一致，不直接断言网络故障。
- 对更早的全局 IPv6 unreachable 阻断显示明确处理提示；不自动删除其他模块的规则，不绕过自检。优先级 100 的阻断与 Android 正常终止规则 32000 不同，应在创建阻断的模块中关闭后重新检查。
